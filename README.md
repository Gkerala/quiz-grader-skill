# quiz-grader: 퀴즈 채점 스킬

AI에게 퀴즈 답을 보내면 **문제 / 내 답 / 정답 / 판정**을 문항마다 나란히 놓고 채점하고, 틀린 것만 일상 비유로 다시 설명해 주는 스킬입니다.

## 불편했던 점
이해 확인 퀴즈를 풀 때마다 같은 요청을 처음부터 다시 했습니다.

- 어떤 날은 한 줄짜리 표만 와서 **내가 쓴 답과 정답을 나란히 비교할 수 없었습니다.** 무엇을 모르는지 알려고 채점을 받는 건데, 비교가 안 되면 소용이 없었습니다.
- 어떤 날은 맞은 문제까지 다시 설명해서 **내용이 길어졌고**, 정작 틀린 문제의 설명이 묻혔습니다.
- 판정 기준(맞음 / 반쪽 / 틀림, "모름"을 어떻게 셀지)이 대화마다 달라서 **지난번 결과와 비교하기 어려웠습니다.**

그때마다 "문제, 내 답, 정답, 판정 순서로, 틀린 것만 비유로 설명해 줘"를 다시 쓰는 일이 반복되는 번거로움이었습니다.

## 해결
채점 형식과 규칙을 `SKILL.md` 한 장에 적어 두었습니다. 채점을 요청하면 AI가 이 스킬을 꺼내 항상 같은 형식으로 답합니다.

- 문항마다 **문제 / 내 답 / 정답 / 판정(○ △ ✕)** 을 한 표에 둡니다.
- "모름"은 ✕로 세되 흠으로 보지 않고 복습 대상으로 모읍니다.
- 총점과 영역별 점수를 한 줄로 요약하고, 이전 결과가 있으면 비교합니다.
- **△와 ✕만** 중요한 순서로 최대 5개, 일상 비유와 비유의 한계까지 붙여 다시 설명합니다.
- 문제 원문이 없으면 정답을 지어내지 않고 문제를 먼저 달라고 합니다.
- 문항이 6개를 넘거나 표로 보고 싶다고 하면 결과를 **HTML 파일 하나**로 저장해 줍니다. 채팅에서는 긴 표가 줄바꿈되거나 화면을 넘겨서 읽기 불편했기 때문입니다. 서버 없이 파일을 열기만 하면 되고, 좁은 화면에서는 카드로 바뀝니다. 속도를 위해 AI는 HTML을 직접 쓰지 않고 채점 내용만 JSON으로 넘기며, CSS와 태그는 `quiz-grader/render.py`(Python 표준 라이브러리만 사용)가 만듭니다.

### 출력 예
```
| 문제 | 내 답 | 정답 | 판정 |
|---|---|---|---|
| 3. 규칙 파일은 대화를 리셋하면 사라진다? | X | X. 파일에 적어 둔 것이라 리셋해도 유지된다 | ○ |
| 7. 스킬에서 description이 중요한 이유 | 효율적으로 쓰려고 | AI가 언제 꺼낼지를 그 한 줄로 판단하기 때문 | △ 이유(판단 기준)가 빠졌음 |
| 9. 서브에이전트의 장점과 대가 | 모름 | 장점은 요약만 가져와 컨텍스트가 덜 어지러운 것, 대가는 토큰이 늘어나는 것 | ✕ |

총 3문제 중 ○ 1, △ 1, ✕ 1

복습 우선순위
1. 서브에이전트: 팀장이 인턴에게 "이것만 조사해 와" 하고 요약 한 장만 받는 것. (한계: 인턴 인건비가 든다)
```

## 설치
스킬은 폴더 하나입니다. `quiz-grader` 폴더를 스킬 폴더에 복사하면 끝입니다. (Claude Code 기준)

```bash
cp -r quiz-grader ~/.claude/skills/
```

한 프로젝트에서만 쓰려면 그 프로젝트의 `.claude/skills/`에 복사합니다. 복사한 뒤 새 대화를 시작해야 스킬 목록에 올라옵니다.

## 쓰는 법
퀴즈 문제와 내 답을 같은 대화에 두고 이렇게 말하면 됩니다.

> 이 퀴즈 채점해줘. (문제와 내 답)

스킬 이름을 부르지 않아도 AI가 `description`을 보고 알아서 꺼냅니다.

## 발동 확인
새 대화에서 아래 두 가지를 시험합니다.

스킬이 호출됐는지는 답변에 "퀴즈 채점" 스킬 호출 표시(Skill 도구 사용)가 뜨는지로 확인합니다. 표 모양만 비슷한 것으로는 구분되지 않습니다.

| 입력 | 기대하는 동작 |
|---|---|
| 퀴즈 문제 3개와 내 답을 주고 "채점해줘" | 스킬 형식(4칸 표, ○△✕, 복습 우선순위)으로 답한다 |
| "HTTP와 HTTPS 차이가 뭐야?" | 스킬을 쓰지 않고 일반 답변을 한다 |

확인 결과 (2026-11-02):
- 1차 시험: 스킬 목록에는 올라와 있었지만 AI가 스킬을 호출하지 않고 직접 채점했습니다. 표 모양은 비슷했지만 Skill 호출 기록이 없었고, 8문제를 채점해도 HTML 파일이 만들어지지 않았습니다. 원인은 `description`이 약해서 "내가 직접 해도 된다"고 판단한 것이었습니다.
- 조치: `description`을 "직접 채점하지 말고 반드시 먼저 이 스킬을 호출한다"로 바꿨습니다.
- 2차 시험: 새 대화에서 8문제를 채점할 때 스킬이 호출되고 HTML 표 파일이 만들어졌습니다. 일반 질문에는 쓰이지 않았습니다.
- 속도 시험 (3차, 같은 산수 8문제·같은 내용, 각 1회): AI가 HTML 전체를 직접 쓴 방식은 약 19초, 채점 내용만 JSON으로 넘기고 `render.py`가 HTML을 만드는 방식은 약 10초였습니다. (스크립트 실행 자체는 0.07초) 두 방식이 만든 파일은 본문 글자와 판정·점수 칸이 같았습니다. 각 1회 측정이라 오차가 있고, 문항이 적을수록 고정 CSS를 안 쓰는 효과가 상대적으로 커집니다.

## 한계
- 정답의 기준은 대화에 올려 둔 강의 노트나 문제 해설입니다. 근거가 없으면 일반 지식 기준이라고 밝히지만 틀릴 수 있습니다. 중요한 건 원본과 함께 확인합니다.
- 서술형 답의 ○ / △ 경계는 AI의 판단이라 이의가 있으면 다시 채점해 달라고 합니다.
- 문제를 새로 만들어 주지는 않습니다. 채점만 합니다.
- 표 파일은 파일을 만들 수 있는 환경(Claude Code, 데스크톱 앱 등)에서만 만들어집니다. 그렇지 않으면 채팅 표로 답합니다. Python이 없으면 AI가 HTML을 직접 쓰므로 그만큼 느립니다.
